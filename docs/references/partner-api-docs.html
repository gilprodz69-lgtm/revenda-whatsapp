1. Overview

Partner API is a REST JSON API for resellers. You integrate it into your shop; when your customer pays you, your backend calls POST /orders and receives instant delivery content.

Catalog
List providers and products with stock, pricing, warranty, duration, bulk tiers, and delivery type.
Orders
Create orders by productId, productSlug, or productCode.
Delivery
Receive a link, coupon code, or ready-account credentials immediately on success.
Usage
Track balance, API order count, spend, request volume, and errors.

Supported delivery types

TypeDescriptionResponse fieldNotes
LINKActivation or subscription URLdelivery.linkUsually safe to forward to your customer.
COUPONRedeemable codedelivery.codeDeliver once; do not log publicly.
READY_ACCOUNTLogin credentials (email/password, etc.)delivery.contentSensitive. Never log or expose in client-side code.

Seat subscriptions, manual activation workflows, and other non-inventory delivery types are not exposed via Partner API.

Shared account model

  • Same Telegram user account as the main bot.
  • Same wallet balance — deposits in the bot fund API purchases.
  • API orders are stored in service_orders with internal source tag partner_api (not returned in API responses).
  • GET /orders returns API orders only, not all bot purchases.
  • The bot’s “My orders” screen shows everything (bot + API).

2. Quick Start

1
Open the Telegram bot → main menu → press API (🔑).
2
Create an API key → enter a name (e.g. Production) → confirm. Copy the full key from the detail screen.
3
Fund your balance via the bot (Binance, on-chain, etc.). Bot balance = API balance.
4
Call the API from your server with Authorization: Bearer YOUR_KEY.
5
Place your first order with a unique externalOrderId from your shop.

Minimal integration script

API="https://ggsoma.store/api/partner/v1"
KEY="sk_live_YOUR_SECRET_KEY"
AUTH="Authorization: Bearer $KEY"

# Health (no auth)
curl -s "$API/health"

# Balance
curl -s "$API/balance" -H "$AUTH"

# Products
curl -s "$API/catalog/products?provider=gemini" -H "$AUTH"

# Create order
curl -s -X POST "$API/orders" -H "$AUTH" -H "Content-Type: application/json" \
  -d '{"productSlug":"gemini-pro-monthly","quantity":1,"externalOrderId":"shop-order-1001"}'

Replace YOUR_SECRET_KEY with the key from the Telegram bot. The base URL https://ggsoma.store/api/partner/v1 is injected when you download this file from the bot.

3. API Keys in the Telegram Bot

Keys are created and managed inside the bot — not via HTTP. This keeps secrets out of admin panels and gives you a simple UI.

Creating a key

  1. API hub → Create key.
  2. Send a key name (2–40 characters: letters, numbers, spaces, . _ -).
  3. Confirm → the full secret is shown on the key detail screen (copyable).

My keys

  • API hub → My keys → tap a key name to open details.
  • The full key is displayed in a copyable block (private chat only).
  • Maximum 3 active keys per account (admin-configurable).

Regenerate

On the key detail screen → Regenerate → confirm. The old secret stops working immediately; update your integration with the new key.

Legacy keys created before encrypted bot storage was enabled cannot display the full secret. Use Regenerate once to get a new viewable key.

4. Authentication (HTTP)

Every protected endpoint requires a Bearer token. Keep the key on your backend only. Never embed it in frontend JavaScript, mobile apps, public Git repos, screenshots, or browser local storage.

Authorization: Bearer sk_live_YOUR_SECRET_KEY

5. Balance & Wallet Model

  • Currency is always USD.
  • API orders deduct from the same bot wallet balance.
  • Charges apply only when order creation succeeds.
  • yourPrice in catalog = your effective reseller unit price (after loyalty/campaign discounts when applicable).
  • Bulk orders (quantity > 1) charge once and return multiple lines[] delivery items.
  • balanceAfter appears only on successful POST /orders (see §11).
{
  "ok": true,
  "balance": "125.50",
  "currency": "USD"
}

10. Order Creation — POST /orders

Request body

FieldRequiredDescription
externalOrderIdYesYour shop’s unique order ID — drives idempotency.
productIdOne of threeNumeric product id.
productSlugOne of threeStable slug (recommended).
productCodeOne of threeInternal product code.
quantityNo (default 1)Max configurable (default 50); also limited by stock.

externalOrderId rules

  • Required on every order.
  • Must be unique per trader account.
  • Use your real shop order id: woo-10452, UUID, shop-{timestamp}, etc.
  • Retry safe: same id + same body → same order, no double charge.

Example — LINK order

Authorization: Bearer sk_live_...
Content-Type: application/json

13. Practical Scenarios

Scenario 1 — Simple shop

1. GET /catalog/products           → display products
2. GET /catalog/products/:slug     → product page (optional)
3. Customer pays on your site
4. POST /orders                    → deliver link/code/content to customer

Scenario 2 — Idempotent retry after timeout

If your HTTP client times out, retry with the same externalOrderId. The API returns the original order without charging twice.

Scenario 3 — Bulk with tier pricing

1. Read bulkDiscount.tiers from catalog
2. POST /orders { quantity: 10, externalOrderId: "bulk-001" }
3. Receive lines[] with 10 separate delivery items

Scenario 4 — Pre-check before purchase

1. GET /balance
2. GET /catalog/products/:slug  → check stock.count and yourPrice
3. Ensure quantity × unitPrice ≤ balance
4. POST /orders

Scenario 5 — Recover old order

GET /orders?externalOrderId=shop-order-1001
GET /orders/SO-20260617-A1B2C3

Scenario 6 — Out of stock

{ "ok": false, "error": { "code": "OUT_OF_STOCK", "message": "Product is out of stock.", "requestId": "req_..." } }

Scenario 7 — Account suspended

{ "ok": false, "error": { "code": "PARTNER_SUSPENDED", "message": "API access is suspended.", "requestId": "req_..." } }

HTTP 403 — contact support via the Telegram bot.

15. Best Practices

Security
Server-side keys only. HTTPS always. Regenerate compromised keys. Never log READY_ACCOUNT delivery.
Reliability
Stable externalOrderId per shop order. Retry POST on timeout with same id.
Pricing
Show yourPrice to customers, not internal catalog/provider costs.
Performance
Cache catalog 60–120s. Exponential backoff on 429. Poll GET /orders/:code only if needed.
Key rotation
Create separate keys for production vs staging. Regenerate from bot when rotating.
Support
Include requestId from error responses when contacting support.

16. Integration Checklist

  • ☐ Create named API key in Telegram bot (private chat).
  • ☐ Store key in server env var — not in frontend.
  • ☐ Implement GET /health check before orders.
  • ☐ Cache catalog; refresh periodically.
  • ☐ Map products by slug in your database.
  • ☐ Send unique externalOrderId per shop order.
  • ☐ Handle idempotent retry (same externalOrderId).
  • ☐ Branch on error.code — especially INSUFFICIENT_BALANCE, OUT_OF_STOCK.
  • ☐ Deliver delivery.* to customer securely.
  • ☐ Log requestId on failures.
  • ☐ Test bulk orders if you sell quantity > 1.
  • ☐ Plan key rotation via bot Regenerate.

17. FAQ

Why does GET /catalog not show the same products as the Telegram bot menu?

The bot menu uses layout rules and showInBot flags. Partner API exposes only instant inventory products with delivery types LINK, COUPON, or READY_ACCOUNT.

Can I retrieve my API key via HTTP?

No. View and copy keys in the Telegram bot under My keys. Use Regenerate if you lost a key.

How many keys can I have?

Up to 3 active keys by default. Each should have a descriptive name (Production, Staging, etc.).

What happens if I retry POST /orders with the same externalOrderId?

You get the original order response. No second charge. balanceAfter is omitted on retry.

Does GET /orders show bot purchases?

No — API orders only. Use the bot for full order history.

What currency and balance are used?

USD. Same balance as your Telegram bot wallet.
